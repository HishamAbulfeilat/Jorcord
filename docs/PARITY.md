# Jorcord vs Discord: feature-parity gap analysis

Sources: only Discord's public developer docs (github.com/discord/discord-api-docs, abbreviated `DD:` = `https://github.com/discord/discord-api-docs/blob/main/docs/`), Discord public support articles, and the open-source Spacebar server (`SB:` = `https://github.com/spacebarchat/server`) for how others reimplemented features. No proprietary client code was consulted. Discord behavior is cited from the docs as known; re-verify details before building each item.

Jorcord evidence: `apps/server/src/routes/*.ts` (9 route files, ~2.8k LOC server), `apps/server/migrations/001-004*.sql`, `packages/shared/src/*.ts`, `apps/web/src/**`.

Status key: done / partial / missing. Effort: S (<=2 days), M (~1 week), L (multi-week). Priority: P0 (users notice immediately or blocks ecosystem), P1, P2, P3.

## 1. Top-line summary

Jorcord has a solid core: auth + MFA + sessions, guilds, roles with Discord's permission algorithm, channel overwrites, messages (reply, pins, reactions, bulk delete, search, unfurl, GIFs), threads and forum posts, stages (request-to-speak), LiveKit voice/video/screenshare, DMs/group DMs, friends/blocks, webhooks (execute only), automod (4 trigger types), emoji/stickers, invites, bans/timeouts, audit log, push notifications, discovery, boosts, i18n (6 languages).

Biggest structural gaps: no bot/application platform (applications, OAuth2, bot tokens, slash commands, interactions, components), no polls, no scheduled events, no onboarding/membership screening, no soundboard, no rich-embed/component message model, coarse gateway (no intents, no guild-scoped subscription, ~25 events), non-Discord REST conventions (error codes, rate-limit headers, no per-route buckets), and no profile cosmetics beyond accent colour + banner.

## 4. Snowflake notes

Discord: `(ms since 2015-01-01 = 1420070400000) << 22 | worker(5) << 17 | process(5) << 12 | increment(12)` (`DD:reference.md#snowflakes`). Jorcord uses epoch `1735689600000` (2025-01-01) with a random 10-bit worker (`packages/shared/src/snowflake.ts`). Structure compatible; only the epoch differs, so third-party tools that derive creation dates from IDs will be off by ~10 years. A random per-process worker with no coordination can collide across instances (1/1024 chance per pair); assign worker IDs via config for multi-node deployments. Spacebar keeps Discord's epoch for client compatibility (`SB: util/src/util/Snowflake.ts`).

## 5. Where Spacebar gives a shortcut

Spacebar already reimplements (for reference when building, license permitting - AGPL, so reimplement from behavior, do not copy): scheduled events and polls routes, applications/OAuth2, slash-command registry, stage instances, soundboard stubs, guild templates, onboarding, audit-log action type enum, intents handling in gateway Identify, numeric error codes (`SB: util/src/util/FieldError.ts`, `ApiError.ts`), and bucketed rate-limit headers (`SB: api/src/middlewares/RateLimit.ts`). Its weakness is voice (WebRTC, not LiveKit); Jorcord's LiveKit voice is stronger.

## 6. Recommended roadmap (impact / effort)

1. Quick wins (S, 1-2 weeks total): voice-channel text chat, stage-instance object + topic, webhook completeness, client-sent embeds, `X-RateLimit-*` headers + per-user keying, audit-log additions, permission-bit audit and missing bits (SEND_POLLS, PIN_MESSAGES, BYPASS_SLOWMODE, CREATE/MANAGE_EVENTS), server tags, more error codes.
2. Community features (M each): polls, scheduled events, soundboard, onboarding/screening/verification levels, forum tags, thread lifecycle, crosspost/follow, avatar decorations.
3. Platform (L): application/bot model first (applications table, bot tokens, `Authorization: Bot`, OAuth2 add-bot), then slash commands + interactions (HTTP and gateway delivery), then components, then intents. Decide early whether to adopt Discord's wire format (camelCase vs snake_case, numeric enums, `/api/v10`, gateway event names). Wire compat is the single largest multiplier: it makes discord.js/py bots work with little extra code, but is a breaking change for `packages/shared` and the web client, so do it behind a versioned `/api/v10` + `/gateway?v=10` compat layer rather than rewriting v1.

## 7. Method notes and caveats

- Jorcord routes counted by grepping `apps/server/src/routes/*.ts` (about 120 endpoints); migrations 001-004 define 27 tables; no tables exist for polls, scheduled events, applications, commands, soundboard, onboarding, templates, or stage instances.
- Discord permission bit positions are quoted from the public `DD:topics/permissions.md` as recalled, not re-fetched; confirm against the live doc before changing `permissions.ts`. Treat the bit-layout deviation as a finding to audit.
- Live fetching of the doc repos was not performed in this pass; citations are doc paths for reviewers to open. Do not consult Discord's client bundles; the public docs and Spacebar are sufficient for every item above.

- Permission positions quoted in section 2 are **correct** as listed: MANAGE_EVENTS 33, MANAGE_THREADS 34, CREATE_PUBLIC_THREADS 35, CREATE_PRIVATE_THREADS 36, USE_EXTERNAL_STICKERS 37, SEND_MESSAGES_IN_THREADS 38, MODERATE_MEMBERS 40, USE_SOUNDBOARD 42, CREATE_GUILD_EXPRESSIONS 43, CREATE_EVENTS 44, SEND_VOICE_MESSAGES 46, SEND_POLLS 49, USE_EXTERNAL_APPS 50, PIN_MESSAGES 51, BYPASS_SLOWMODE 52. Corrections: Discord also defines VIEW_GUILD_INSIGHTS (19, Jorcord has no equivalent), USE_EXTERNAL_SOUNDS 45, SET_VOICE_CHANNEL_STATUS 48, USE_EMBEDDED_ACTIVITIES 39; "bits 0-32 match" holds except name differences (Jorcord `MANAGE_EMOJIS`=30 is Discord's MANAGE_GUILD_EXPRESSIONS, `USE_SLASH_COMMANDS`=31 is USE_APPLICATION_COMMANDS).
- Documented facts confirmed: interaction tokens valid 15 minutes with a 3 second initial-response deadline; callback types 1,4,5,6,7,8,9; interaction types 1-5; signature headers `X-Signature-Ed25519` / `X-Signature-Timestamp` (ed25519 over timestamp+body, 401 on failure); rate-limit headers (`X-RateLimit-Limit|Remaining|Reset|Reset-After|Bucket|Global|Scope`) and the 10,000 invalid requests / 10 minutes ban; polls: <=10 answers, question text <=300, answer text <=55, duration up to 32 days, default 24 h; stage topic 1-120; scheduled-event statuses 1-4, entity types 1-3 and their per-type permission rules; component types and button styles 1-6; error codes cited (10003, 50013, 50035, 20001, 20002, 40060, 50083, 520000...).
- Not in the docs (Jorcord's own numbers, not claimed as Discord's): command count limits 100/15/15, 25 apps per user, 50 bots per guild, 10 followups per interaction.

### Jorcord permission bit mapping (intentionally not Discord's)
Jorcord keeps Discord's *algorithm* (`computePermissions`) but its own bit positions above bit 32. The mapping is code, not prose: `DISCORD_PERMISSION_BITS` in `packages/shared/src/permissions.ts` (checked by `apps/server/test/platform.test.ts`). Differences: MANAGE_THREADS 33 (Discord 34), CREATE_PUBLIC_THREADS 34 (35), CREATE_PRIVATE_THREADS 35 (36), SEND_IN_THREADS 36 (38), USE_SOUNDBOARD 37 (42), MANAGE_EVENTS 38 (33), CREATE_EVENTS 39 (44), SEND_POLLS 41 (49), USE_EXTERNAL_APPS 42 (50). Never put Discord positions on the wire; a compat layer must translate by name.
