# Translations

UI strings are English source text: `t('Cancel')`. A locale file maps English to the translation; a missing key falls back to English.

| Locale | Tag | Source | Status |
|---|---|---|---|
| Spanish, French, German, Turkish, Arabic (RTL) | es-ES fr-FR de-DE tr-TR ar | `apps/web/scripts/i18n-table.tsv` | original set |
| Portuguese (Brazil), Russian, Hindi, Indonesian, Japanese, Chinese (Simplified), Korean, Italian, Dutch, Polish | pt-BR ru-RU hi-IN id-ID ja-JP zh-CN ko-KR it-IT nl-NL pl-PL | `apps/web/scripts/i18n-table-2.tsv` | **MACHINE TRANSLATED** (package D) |

**The ten locales added by package D are machine translations and have not been reviewed by native speakers.** They cover the same core UI chrome as the first five (222 strings: navigation, settings, friends, voice, onboarding). Expect awkward phrasing, wrong register and some wrong terms (for example "Boost", "Deafen", "Stage"). They are good enough to make the app usable, not to ship as polished. Strings that are not in the table (newer features) show in English.

## Workflow

1. List what the code asks for: `node apps/web/scripts/i18n-keys.mjs`.
2. Edit the TSV (first column = English key, then one column per locale). Keep `{placeholders}` identical.
3. Regenerate: `node apps/web/scripts/i18n-gen.mjs` (rewrites `apps/web/src/i18n/{pt,ru,hi,id,ja,zh,ko,it,nl,pl}.ts`). Edit the TSV, not the generated files.
4. Register a new locale in `apps/web/src/i18n/index.ts` (`LOCALES` + `DICTS`) and `detectLanguage` in `stores/ui.ts`.
5. `pnpm --filter @jorcord/web test i18n`. `i18n.test.ts` fails on any locale with extra or missing keys, an empty value, or changed placeholders.

Native-speaker review: send a PR that edits the TSV and removes the locale from the machine-translated row above once reviewed.
